# myskills - Agent Configuration

## Root Configuration

Inherits all behavior from `/AGENTS.md` at the monorepo root. Local rules extend or override the root file for this repository.

## Project Context

`myskills` is the template-derived `skillsbase` repository that publishes the managed install surface for `newbe36524/myskills`. It uses `@hagicode/skillsbase` for CLI operations.

## Working Directory

Run commands from `repos/myskills/`.

## Key Commands

```bash
npm install
npm install --global @hagicode/skillsbase
npm run sync
npm run sync:check
npm test
```

Requires Node.js 24+. The `skillsbase` CLI must be installed globally (as CI does) before `sync` / `sync:check`.

## Key Paths

- `skills/`: managed skill output (generated by `skillsbase sync`)
- `sources.yaml`: single source of truth for the manifest and the managed skill sources
- `tests/`: repository tests (`repository-contract.test.mjs`)
- `docs/maintainer-workflow.md`: maintainer flow and ownership audit
- `.github/`: managed workflows and composite actions (regenerate with `skillsbase github_action --kind all --repo .`); `skills-sync.yml` validates sync on pull requests and pushes to `main`, and `skills-manage.yml` is a manual `add` / `remove` / `sync` dispatch

## Agent Guidelines

- Use `npm run sync` to refresh the managed `skills/` output; never edit it manually.
- Use `npm run sync:check` in CI to verify sync consistency.
- `@hagicode/skillsbase` is the only supported CLI for maintenance.
- Keep the managed block structure consistent with the `skillsbase-template` baseline; do not reintroduce ad hoc root scripts such as `scripts/sync-skills.mjs`.
- Add or remove managed skills by editing `sources.yaml` and running `npm run sync`, not by editing `skills/`.
